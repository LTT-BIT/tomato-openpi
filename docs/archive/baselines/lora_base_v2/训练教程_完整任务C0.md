# 完整任务 C0 v2：多人协作训练说明

版本：`fulltask_c0_v2`，2026-10-09。配置入口为同目录 `pi05_fr3_wuji_fulltask_c0_train.py`。
使用准备好的一个完整任务 LeRobot 数据集，全部纳入训练，不划分训练集和验证集。
本版新增确定性无放回采样、独立随机种子、采样清单与恢复检查；模型及优化器超参数沿用 1002。
跨机器逐 bit 一致性不作为本轮目标，不要求同机器；仍记录代码和依赖版本供协作核对。

**交给同事时必须提供本次修改后的完整 Pi05 仓库及对应 commit，不能只复制这一个配置到旧仓库。**
新增的功能依赖 `src/openpi/training/sampling.py`、`reproducibility.py` 和本版训练入口、数据加载器、模型代码。
本配置无需注册到 `config.py`。历史 1002 配置默认仍使用 `legacy` 采样，不能与 v2 混称同一基线。

## 1. 填写配置

打开同目录的 `pi05_fr3_wuji_fulltask_c0_train.py`，修改文件顶部四项：

```python
DATASET_REPO_ID = "fr3_wuji/你的数据版本"
DATASET_ROOT = "/你的/已准备好的数据目录"
NORM_ASSETS_DIR = "/你的/归一化统计父目录"
NORM_ASSET_ID = "统计子目录名"
```

归一化文件的实际位置为 `NORM_ASSETS_DIR/NORM_ASSET_ID/norm_stats.json`，使用与本次数据对应的已准备好统计。
训练直接读取数据中的完整任务英文指令；文件中的 `FULL_TASK_PROMPT` 只是示例，不会覆盖数据标签。

默认路径是占位示例，本机尚无该完整任务数据和统计。必须先填实际路径；数据应为标准 LeRobot 格式，包含 `meta/`、`data/` 及相应视频。代码不自动合并其他目录，不把子任务片段转换为完整轨迹。

基线固定：双 LoRA（VLM rank 16、Expert rank 32）、视觉编码器可训练、30 Hz、54 维、horizon 50、batch 8、20k steps；其余模型、优化器和学习率参数保留 1002 配置。

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `sampling_mode` | `epoch_shuffle` | 单数据集逐轮无放回洗牌 |
| `seed` | 42 | flow matching 噪声、时间采样的基础随机流 |
| `model_seed` | 42 | 模型中需初始化的参数 |
| `data_seed` | 42001 | 样本索引排列，独立于 worker 随机数 |
| `augmentation_seed` | 42002 | 每步图像增强，独立于模型噪声 |
| `num_workers` | 8 | 数据加载并行度 |
| `wandb_enabled` | True | 默认启用 W&B，命令同时保留本地日志 |

四项 seed 必须配套记录。仅修改 `--seed` 不会自动改变其他三项。
独立 seed 为 `None`、采样模式为 `legacy` 时保留旧配置行为；v2 显式填写上述参数。

## 2. 采样规则与覆盖率

每轮对全部 N 个帧索引做一次随机排列，各轮连接成连续样本流，再每 8 个组成一个 batch。
轮次结束剩余不足 8 个时，从下一轮开头继续取；不丢弃尾部，不产生变长 batch。
每轮内无重复，不同轮之间可重复；跨轮 batch 中出现相同帧是正常情况。
排列使用显式 `PCG64 + SeedSequence([data_seed, epoch])`，版本标识 `epoch_shuffle_pcg64_v1`。
完整数据列表、代码、依赖及 seed 一致时，数据顺序可重建，不依赖 worker 预取游标。

总采样量为 `batch_size × num_train_steps`。要至少覆盖一遍，需满足 `num_train_steps >= ceil(N / batch_size)`。
例如 N=78,868、batch=8 时，第 9,859 步内已覆盖一遍；20k 步提供 160,000 次采样，约 2.03 轮。
这个数字只是用历史 1002 数据量举例，不代表 v2 已接入那份子任务数据。
启动时记录计划覆盖率，预算不足时给出警告；不是无论多少数据都能在 20k 步用完。

覆盖率以作为输入观测/动作窗口起点的不同帧计数。horizon 50 的动作窗口会重叠，不能把 `160000 × 50` 当成不同观测覆盖量。
当前 v2 支持 JAX 入口、一个显式本地路径的标准 LeRobot 数据集。多数据集传入 `epoch_shuffle` 会报错；多数据集加权重采样仍属于旧 `legacy` 路径，不保证逐轮全覆盖。本版不添加关键阶段过采样比例。

## 3. 启动训练

在 Pi05 仓库根目录执行。命令默认已有可用 `.venv`、模型/tokenizer 资产和准备好的数据。
每次新实验使用不同的 `EXP`：

```bash
cd /home/descfly/workspace/Pi05
export EXP=tomato_D01_fulltask_C0v2_s42_run01
export WANDB_MODE=online
mkdir -p logs
set -o pipefail
JAX_PLATFORMS=cuda PYTHONNOUSERSITE=1 \
XLA_PYTHON_CLIENT_PREALLOCATE=true XLA_PYTHON_CLIENT_MEM_FRACTION=0.90 \
.venv/bin/python -u -m training_baseline.lora_base_v2.pi05_fr3_wuji_fulltask_c0_train \
  pi05_fr3_wuji_fulltask_c0_30hz \
  --exp-name "$EXP" --seed 42 --model-seed 42 \
  --data-seed 42001 --augmentation-seed 42002 --wandb-enabled \
  2>&1 | tee "logs/${EXP}_$(date +%Y%m%d_%H%M%S).log"
```

换机器时修改 `cd` 路径及数据/统计位置，保留完整仓库结构，用上面的 `-m` 命令启动。
首次使用 W&B 可执行 `.venv/bin/wandb login`；无法联网时把 `WANDB_MODE` 改为 `offline`，之后用 `.venv/bin/wandb sync <实际offline-run目录>` 补传。

新机器还没有 Python 环境时，在仓库根目录先执行：

```bash
GIT_LFS_SKIP_SMUDGE=1 uv sync --frozen --python 3.11
GIT_LFS_SKIP_SMUDGE=1 uv pip install -e .
```

首次启动及每次续训会读取 `meta/`、`data/`、`videos/` 中的文件计算 SHA-256，并保存实际加载表的帧映射。
这会增加启动磁盘读取时间，期间日志会显示进度；不是重新转换数据或验证视频语义。
训练期间不要改动共享数据、统计或运行中的源码。数据修改建立新版本和新 EXP。

## 4. 查看结果、审计与续训

日志保存在 `logs/`，正常完成 20k 步时，最终权重通常为：

```text
checkpoints/pi05_fr3_wuji_fulltask_c0_30hz/<EXP>/19999/
```

实验根目录还会生成 `reproducibility/`：

| 文件 | 用途 |
| --- | --- |
| `sample_indices.npy` | 本实验全部采样索引，按 batch 连续排列 |
| `samples.csv` | 每次采样的位置、step、batch 内位置、数据集 ID、数据索引、episode 和帧号 |
| `dataset_manifest.json` | 相对路径文件哈希、数据量、实际帧映射指纹及任务文本 |
| `norm_stats.json` | 实际加载的归一化统计审计快照；部署仍使用 checkpoint 的 `assets/` |
| `effective_config.json` | CLI 覆盖后的实际配置 |
| `summary.json` | 计划采样量、不同起始帧覆盖率、覆盖一遍所需步数及哈希 |
| `manifest.json` | 采样器版本、配置约束、源码指纹、Git commit 和审计文件哈希 |

`summary.json` 和 W&B 中 `sampling/planned_*` 表示整个目标预算的计划覆盖，不能证明中断的实验已经用完这些数据。实际使用到的位置由 checkpoint 的 `train_state.step × batch_size` 决定。
训练日志及 W&B 另记录 `sampling/consumed_samples`、`sampling/consumed_unique_frames` 和 `sampling/consumed_coverage`，表示已执行优化步对应的实际采样覆盖；进程异常退出时以最后保存的 checkpoint 为恢复依据。

同一次实验中断后，使用相同配置、数据和 EXP，在启动命令后加 `--resume`。
恢复使用 `train_state.step`（已完成的优化步数），从对应采样位置继续；不能用 checkpoint 文件夹名直接乘 batch。
例如文件夹 `1999` 正常对应已完成 2,000 步，接下来从位置 16,000 取 batch。worker 已预取但未训练的样本不会被跳过。

续训需要完整 step checkpoint（含 `train_state`）以及实验根目录的 `reproducibility/`、`wandb_id.txt`。
v2 会核对数据内容、统计、随机种子、模型/优化参数、采样预算、源码和采样文件；不匹配时停止并要求新建实验。
本版不允许用 `--resume` 修改 batch 或追加总步数；20k 是这次实验的总目标步数。
历史没有采样审计文件的 checkpoint 不能直接转成 v2 续训。恢复失败时不要删除审计文件绕过检查。
新实验使用新 EXP，不使用 `--overwrite`。训练已经到达目标步数时，恢复入口报告完成，不再取 batch。

## 5. 多人对比约定

开发阶段先使用一组共同种子。正式结论建议运行三组配对实验：

| 重复编号 | `seed` | `model_seed` | `data_seed` | `augmentation_seed` |
| --- | --- | --- | --- | --- |
| s42 | 42 | 42 | 42001 | 42002 |
| s43 | 43 | 43 | 43001 | 43002 |
| s44 | 44 | 44 | 44001 | 44002 |

每个方案都使用同样三行参数，改 EXP 并在 CLI 中同时覆盖四个 seed。比较各组配对差值，报告三组结果、均值和标准差，不只选最好的一次。

同一数据上的模型/优化器对比，固定数据版本、任务文本、归一化、初始基础权重、batch、总步数及采样种子，只改变本轮研究变量。
先核对 `dataset_sha256` 和 `plan_indices_sha256`：两个都相同才说明输入帧身份和顺序一致。
还应核对 `norm_sha256` 和增强 seed；采样哈希相同不等于模型增强和归一化相同。

比较不同数据版本时，数据和采样哈希通常不同，应事先说明采用固定总步数还是固定数据轮次。本 C0 默认固定 20k 步、batch 8，数据量不同意味着遍历轮数不同，不能称为“每步看到相同数据”。
本次不划分训练/验证集，因此训练 loss 只作为训练状态指标，不把它当作泛化成绩；效果按固定实机任务、物体设置、prompt 和成功判据评价，记录成功次数/总次数。

每次实验归档：实验编号、负责人、baseline 版本、Git commit、完整命令、本地日志/W&B、数据来源与版本、四项 seed、实际配置、三个关键哈希、训练完成步数、权重路径及实机结果。不要只交换一个改过但未注明版本的配置文件。

## 6. 部署与交付范围

部署使用本次实际配置、完整任务英文 prompt、checkpoint 的 `params/` 与配套 `assets/`；不能使用旧四阶段 prompt 或别的数据统计。
`FULL_TASK_PROMPT` 是示例；实际英文指令从数据读取并记录在 `dataset_manifest.json` 的 `tasks` 中，团队应统一使用其中的完整任务指令。
采样器和随机种子是训练行为，不改变 54 维动作顺序、30 Hz 时间轴和 horizon 50 的部署接口。

本版做采样、审计和断点恢复的自动化验证；未用默认完整任务数据启动正式 GPU 训练，未做实机验证。
