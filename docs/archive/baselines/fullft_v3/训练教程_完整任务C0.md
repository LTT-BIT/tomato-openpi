## 3. 采样、训练与日志

每轮以 `PCG64 + SeedSequence([data_seed, epoch])` 对全部帧索引做随机排列，各轮连接成连续样本流，每 8 个组成 batch。
轮内无重复，轮尾不足 8 个时接下一轮样本，不丢尾帧。版本为 `epoch_shuffle_pcg64_v1`。
三套输入先合并为一个数据集，满足原 v2 的单数据集约束；不使用加权有放回混合器。

481,223 帧、batch=8，完整覆盖一轮需 ceil(481223/8)=60,153 步。
计划共采样 481,224 次，最后补 1 个下一轮样本。改成 20k 步只能覆盖约 33.25% 的观测起始帧。
horizon 50 的动作窗口彼此重叠，不能把采样量乘 50 当成不同观测覆盖量。

```bash
cd /home/zhiwei/workspace/code/pi05
export EXP=tomato_all_full_fullft_30hz_s42_run01
export WANDB_MODE=online
bash training_baseline/fullft_v3/scripts/train_all_full.sh
```

若官方权重仍在下载，且 8 卡被其他任务占用，可在完成下载任务已启动后运行等待器（把实际下载进程 PID 传入）：

```bash
source training_baseline/fullft_v3/scripts/env.sh
"$UV_PROJECT_ENVIRONMENT/bin/python" -u -m training_baseline.fullft_v3.scripts.launch_when_idle \
  --download-pid 12345 --download-pid 67890 \
  --experiment tomato_all_full_fullft_30hz_s42_run01
```

等待器要求 8 卡连续三次检查均低于 1 GiB 显存和 5% 利用率，并要求运行盘剩余至少 300 GiB；不停止占用 GPU 的其他进程。状态见运行目录的 `tomato_all_full_fullft_30hz_s42_run01-launch-status.json`；`first_step_complete` 表示完成了第一步，`failed` 表示需检查同目录启动日志。

脚本默认看到 GPU 0–7，全局 batch=8，JAX 将数据分到各卡，每卡 1 个样本。
`fsdp_devices=1` 表示参数/优化器在各卡复制；新实验可传 `--fsdp-devices 8` 做参数分片，不能在运行中改变。
可用 `CUDA_VISIBLE_DEVICES` 限定显卡；全局 batch 必须能被可见卡数整除。
脚本禁用 JAX 预分配，TMPDIR 和缓存使用运行目录。所有 CLI 覆盖项都会记录进实际配置。

stdout/stderr 同时保存在仓库 `logs/` 的北京时间戳文件，并启用 W&B 项目 `openpi`。
首次使用运行 `"$UV_PROJECT_ENVIRONMENT/bin/wandb" login`，凭据不写进 Git。
无法联网时设 `WANDB_MODE=offline`，联网后用 `"$UV_PROJECT_ENVIRONMENT/bin/wandb" sync <offline-run目录>` 补传。
本机基础权重由上述校验程序预先缓存；首次启动仍可能下载 tokenizer。准备完成与训练完成分别记录。

## 4. 审计与同一实验恢复

首次启动/每次恢复都会计算 metadata、Parquet、视频文件 SHA-256，并记录实际帧映射；这会增加启动读盘时间。
训练期间不修改共享输入、统计或源码。实验目录中的 `reproducibility/` 包含：

| 文件 | 内容 |
| --- | --- |
| `sample_indices.npy`、`samples.csv` | 完整采样计划和 step/episode/frame 映射 |
| `dataset_manifest.json` | 数据文件哈希、帧映射、英文 tasks |
| `norm_stats.json` | 实际统计审计快照 |
| `effective_config.json` | CLI 覆盖后的实际配置 |
| `summary.json` | 计划覆盖率、覆盖一轮所需步数和关键哈希 |
| `manifest.json` | 随机种子、模型/优化器约束、源码、锁文件与审计文件哈希 |

计划覆盖不能证明中断的实验已用完数据。实际消费位置由 `train_state.step × batch_size` 确定；worker 已预取但未训练的样本不跳过。
恢复需完整 step checkpoint（含 `train_state/`、`params/`、`assets/`）及实验根目录的审计文件、`wandb_id.txt`：

```bash

```

恢复必须使用原数据、统计、seed、batch、总步数、模型/优化参数与源码。校验不一致会停止，不删除审计文件绕过检查。
本次 `run01` 的审计记录了整理目录之前的源码路径和哈希；若要严格恢复该实验，使用原训练提交 `4d9b349af63cd2cdd8ffb67d579eff04a30b34e5`，不能直接在整理后的目录运行同一实验的 `--resume`。
