# π0.5 完整任务 C0：从零准备到训练交接

日期：2026-10-09。本教程与 `pi05_fr3_wuji_fulltask_c0_train.py` 配套。
该文件是可直接执行的 Python 训练配置，不是描述性 YAML，也不需要注册进 `src/openpi/training/config.py`。
需要匹配的 Pi05 仓库、依赖、数据和预训练资产；单独一个 Python 文件不能替代这些依赖。

## 1. 基准是什么，去掉了什么

以已核对的 1002 配置为来源，保持模型、优化器、冻结规则和训练预算一致；改为完整任务数据、新统计与一条完整任务指令。新配置名为 `pi05_fr3_wuji_fulltask_c0_30hz`，默认实验名为 `tomato_fulltask_c0_30hz_s42`。

1002 的 subtask 不是一个模型开关，而是数据已按阶段切分，并标注四种任务指令。本基准：

- 一个 episode 对应一条真实、连续的完整任务示范，不重新切分四个子任务。
- 一条完整英文任务指令贯穿 episode；部署时使用同一条指令，不需要四阶段 prompt 切换。
- 保留 `prompt_from_task=True`：这表示从数据读取语言指令，不代表开启子任务。
- 仍用 50 步滑动动作窗口训练；“完整任务”不代表一次输出整条轨迹。
- 不自动拼接旧子任务，不把短片段改名后当成完整任务，也不保证机器人学会自动完成所有阶段。

完整英文指令以配置中的 `FULL_TASK_PROMPT` 为准：

> Pick up a tomato truss with the right hand and hold it steady between both hands, then pick a single cherry tomato from the truss with the left hand and place the picked tomato into the plate on the left.

含义：右手拿起并在双手之间握稳番茄串，左手摘取一颗番茄，再放入左侧盘子。该文本是本轮完整任务基准的新指令，并非原 1002 已验证的完整任务标签。若实际容器是篮子或任务流程不同，统一修改配置常量和对应数据标签，建立新版本，部署同步使用，不能让各人自行改写。

## 2. 固定参数

| 项目 | C0 设置 |
| --- | --- |
| 初始化 | `gs://openpi-assets/checkpoints/pi05_base/params`，PartialCheckpointWeightLoader，允许 action/state 投影形状不匹配时跳过 |
| 模型 | π0.5，bfloat16，action_dim 54，horizon 50，max_token_len 256，discrete_state_input=True |
| VLM LoRA | gemma_2b_lora，attn/ffn，rank=alpha=16 |
| Expert LoRA | gemma_300m_lora，attn/ffn，rank=alpha=32 |
| 冻结 | 复用 1002 `model.get_freeze_filter()`；视觉编码器及未被过滤的投影层可训练，不是仅训练 adapter |
| 输入 | 三路 RGB、关节状态、一条英文任务指令 |
| 动作 | 30 Hz，50 步约 1.67 秒；双臂 delta、双手绝对位置；分位数归一化 |
| 训练 | batch 8、workers 8、seed 42、20,000 steps、fsdp_devices=1、EMA 关闭 |
| 学习率 | cosine；warmup 1,000，peak 2.5e-5，decay_steps 30,000，decay_lr 2.5e-6 |
| AdamW | b1=0.9，b2=0.95，eps=1e-8，weight_decay=1e-10，clip_gradient_norm=1.0 |
| 记录与保存 | log_interval 10、save_interval 2,000、keep_period 10,000 |
| 其他 | video_backend=pyav、单数据集 weight=1、resume=False、overwrite=False |

配置文件显式列出 TrainConfig 参数。图像增强、tokenizer、采样和 transform 的实现仍由仓库决定，因此必须固定代码 commit 和 `uv.lock`；不能保证同一个配置在任意修改过的仓库中行为完全一致。文件保留的 PyTorch 字段不代表本教程使用 PyTorch，实际入口调用 JAX 训练循环。

## 4. 数据准备：使用完整轨迹

默认数据目录是 `./data/fr3_wuji/tomato_fulltask_v1`，并不随配置文件提供。
A/B 是数据质量等级，不是采集员身份。专采的 A-subtask/B-subtask 已被切段，不能直接作为本基准的完整任务输入：优先找回对应原始连续采集，再转换；不能盲目拼接独立片段。

先固定本次采集清单、质量级别、采集员、过滤规则和数据版本。需离线验证时，先按原始采集轨迹划分训练/验证，再做后续处理，归一化只使用训练数据。

### 4.1 转换原始采集

仓库转换器适用于“一个目录下面多条单 episode 的 LeRobot v2.0 采集、每条带 dataloader.py”的原始布局；其他格式需先适配，不能只改路径套用。
下面设置原始采集目录，然后输出新目录。命令不启用 overwrite：

```bash
export SOURCE_ROOT=/data/raw/tomato_fulltask_v1
export TASK_PROMPT="$(PYTHONNOUSERSITE=1 .venv/bin/python -c 'from pi05_fr3_wuji_fulltask_c0_train import FULL_TASK_PROMPT; print(FULL_TASK_PROMPT)')"
PYTHONNOUSERSITE=1 .venv/bin/python examples/fr3_wuji/convert_dataset.py \
  --src-root "$SOURCE_ROOT" \
  --repo-id fr3_wuji/tomato_fulltask_v1 \
  --root ./data/fr3_wuji/tomato_fulltask_v1 \
  --task "$TASK_PROMPT"
```

转换器会为每条输入采集写同一任务指令，它不判断源轨迹是否完成任务；先检查源视频。已转换且满足下面契约的数据不必重复转换，但应另建版本统一任务标注，保留原始文件，不要覆盖共享数据。

### 4.2 数据契约与核验

- LeRobot metadata：`meta/info.json`、`tasks.jsonl`、`episodes.jsonl`；另有 `data/` 和 `videos/`。
- `tasks.jsonl` 只含一条 `FULL_TASK_PROMPT`；每条 episode 的 `tasks` 为该指令的单元素列表；Parquet 的 task_index 与该任务索引一致。
- 图像键 `observation.images.cam0/cam1/cam2`，分别对应头部、左腕、右腕。
- 原始 state 可为仓库定义的 108 维，在线取位置并重排；54 维 state 必须已是左臂7、左手20、右臂7、右手20。
- 原始 action 为 54 维，顺序左臂7、右臂7、左手20、右手20；在线变换后才是左臂7、左手20、右臂7、右手20。不能对 action 提前重排两次。
- 关节位置单位 rad；输入为绝对动作目标，不要提前做臂部 delta。
- 源数据 metadata FPS 至少为 30；本基准按 30 Hz 取动作，不跨 episode 窗口，末尾重复最后动作。相机原始 FPS 可以不同，需正确同步。

转换后，与原始数据抽样比对；SOURCE_ROOT 沿用上一节：

```bash
PYTHONNOUSERSITE=1 .venv/bin/python -m examples.fr3_wuji.verify_dataset \
  --src-root "$SOURCE_ROOT" --repo-id fr3_wuji/tomato_fulltask_v1 \
  --root ./data/fr3_wuji/tomato_fulltask_v1 --episodes 2
```

此命令抽样核对源与转换结果，不能替代整个训练集的视频、成功质量和任务完整性审查。合并多个已转换数据可使用 `examples/fr3_wuji/merge_lerobot_datasets.py --help`，该工具不负责重复轨迹的自动去重。

## 5. 计算本数据的归一化统计

默认统计目录：`./assets/fulltask_c0/tomato_fulltask_v1_30hz`。不要复用 1002 子任务 norm。
以下命令从本配置获取数据路径，明确使用 30 Hz、50 步 horizon 的现有 FR3/Wuji 统计函数，保留 prompt。输出存在时停止，避免覆盖正在使用的统计：

```bash
PYTHONNOUSERSITE=1 JAX_PLATFORMS=cpu .venv/bin/python - <<'PY'
from pathlib import Path
from pi05_fr3_wuji_fulltask_c0_train import build_config, validate_inputs
from scripts.prepare_fr3_wuji_20hz import compute_stats
cfg = build_config()
validate_inputs(cfg, require_norm=False)
assert cfg.model.action_horizon == 50 and cfg.data.action_hz == 30.0
assert len(cfg.data.lerobot_datasets) == 1
out = Path(cfg.data.assets.assets_dir) / cfg.data.assets.asset_id
if out.exists():
    raise FileExistsError(f'请选择新的统计版本目录或确认已完成的统计: {out}')
compute_stats(
    (Path(cfg.data.lerobot_datasets[0].root),), out, 256,
    action_hz=30.0, rewrite_prompt=False,
)
PY
```

函数所在文件名含 20hz，但这里显式使用 30 Hz。它扫描动作窗口，执行状态/动作重排与双臂 delta，写出 `norm_stats.json` 和 `provenance.json`。修改 horizon、采样方式或动作表示后，不能直接复用这段固定统计流程。

检查配置、任务标签及归一化：


读取一个实际 batch（CPU，不训练模型；tokenizer 需可用）：


## 7. 恢复训练与 checkpoint

默认输出：

```text
checkpoints/pi05_fr3_wuji_fulltask_c0_30hz/<EXP>/19999/
  params/
  assets/tomato_fulltask_v1_30hz/norm_stats.json
  train_state/
```

20k 正常完成时最终通常是 19999，以实际记录为准。每 2k 保存不代表所有中间点都永久保留，代码保留最新及 keep_period 对齐的步骤。等待 checkpoint 异步写入完成后再复制。

同实验恢复：复用第 6 节命令、同一 EXP、数据和覆盖参数，在 `--wandb-enabled` 后增加 `--resume`。需要完整 train_state，部署包仅有 params/assets 不足以续训。`num_train_steps` 是总目标步数，不是追加步数；无有效 checkpoint 时入口可能重新初始化，必须核对日志。
不要用 `--overwrite` 解决重名，它会删除原实验 checkpoint。换数据做第二阶段应另建实验并记录父权重、额外步数、优化器是否重置，不属于同实验断点恢复。

## 8. 同事如何在基准上实验

推荐每个人保留一份不可修改的 C0 附件，在自己的实验分支复制该 Python 文件作为工作配置，仍使用教程中的根目录文件名，并在飞书上传该次实际文件及与 C0 的差异。一次正式运行一个记录。

数据对照时只修改 `build_config()` 的四个默认值：`repo_id`、`dataset_root`、`assets_dir`、`asset_id`，并为运行设置唯一 EXP。随后重新执行本教程的数据检查、统计和 batch 检查；这些流程都会读取同一份配置，避免训练与统计不一致。模型和优化参数保持不变。

也可用 CLI 覆盖，但五个字段需要配套填写，并确保第 5 节生成统计时采用同一组参数：

```text
--data.repo-id <逻辑数据ID>
--data.lerobot-datasets.0.repo-id <同一逻辑数据ID>
--data.lerobot-datasets.0.root <实际数据目录>
--data.assets.assets-dir <统计父目录>
--data.assets.asset-id <统计子目录名>
```

数据比较取得结果后，再逐项改学习率、微调方式等。修改模型 variant 时须同步核对冻结规则和文件中的 LoRA rank 校验，不能靠绕过校验宣称仍是 C0。
完整任务基准与旧 1002 子任务模型评测口径不同，不能把成功率差异全归因于去掉 prompt 切换。

最低归档项：代码 commit、实际 Python 配置、完整启动命令、数据清单、norm/provenance、英文 prompt、负责人、日志/W&B、实际步数、评测权重路径与成功次数/总次数。保存配置和 norm 的 SHA-256；仅配置文件哈希不能覆盖命令行变化。

## 9. 训练后部署交接

本配置名未注册到 config.py，不能直接传给 `scripts/train.py`、`compute_norm_stats.py --config-name` 或通用服务端的 `--policy.config`。训练使用本文件；部署由相同的 `build_config()` 加载配套权重和统计。
下面是仅启动策略服务的 Python 用法，将 CKPT 替换为本次实际路径。它加载 GPU 模型，但不连接机器人、不下发动作：

```bash
export CKPT="$PWD/checkpoints/pi05_fr3_wuji_fulltask_c0_30hz/$EXP/19999"
PYTHONNOUSERSITE=1 JAX_PLATFORMS=cuda .venv/bin/python - <<'PY'
import os
from pi05_fr3_wuji_fulltask_c0_train import build_config, FULL_TASK_PROMPT
from openpi.policies import policy_config
from openpi.serving import websocket_policy_server
cfg = build_config()
policy = policy_config.create_trained_policy(cfg, os.environ['CKPT'], default_prompt=FULL_TASK_PROMPT)
websocket_policy_server.WebsocketPolicyServer(policy, host='0.0.0.0', port=8000).serve_forever()
PY
```

`build_config()` 必须来自此次训练实际配置，尤其 asset_id；服务读取 checkpoint 内统计，不要替换成其他数据的统计。default_prompt 只在请求没有 prompt 时填充，客户端若主动发送 prompt，必须发送同一完整任务指令，不能继续发送旧四阶段指令。
输入键是 `observation/image`、`observation/left_wrist_image`、`observation/right_wrist_image`、`observation/state`、`prompt`。
输出为 `(50,54)`，顺序左臂、左手、右臂、右手，已反归一化并还原双臂绝对目标。执行端不得重复做 delta 还原。模型时间轴 30 Hz 不等于设备命令下发频率。
具体机器人接入仍按仓库现有 FR3/Wuji 部署说明核对服务地址、动作顺序和执行配置。所有数据基线采用同一部署协议；整任务自主成功与人工辅助/阶段成功分别记录。
