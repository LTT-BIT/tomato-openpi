# 训练使用说明

本教程针对分层配置的 JAX 训练流程，包含数据、统计、日志、W&B 与恢复，不包含部署操作。

## 环境

在仓库根目录执行：

```bash
export PI05_RUNTIME_DIR=/你的本地磁盘/pi05-runtime
bash scripts/setup_training_env.sh
source scripts/training_env.sh
```

使用 Python 3.11 和 uv sync --frozen，可通过 PI05_PYTHON 选择已有解释器。环境默认位于 `$PI05_RUNTIME_DIR/venv`，缓存、临时文件、日志和 W&B 放在运行目录；未设置时默认 `.runtime/`。保留原 JAX/Torch 和 LeRobot revision，移除 gym-aloha、MuJoCo 与 websocket 运行时依赖；RLDS 依赖仍为可选组。

默认关闭 JAX 显存预分配；每人显式选择 GPU，batch 必须能被可见设备数整除。历史 v3 使用 8 张可见 GPU、fsdp_devices=1，本轮不自动占用 GPU 启动训练。

## 数据和统计

| 数据配置 | 默认数据位置 | 默认统计位置 | 状态 |
| --- | --- | --- | --- |
| `tomato_fr3_fulltask_v1` | `$PI05_RUNTIME_DIR/data/tomato_fulltask_v1` | `assets/fulltask_c0/tomato_fulltask_v1_30hz/` | 占位路径；原记录未确认已准备或训练完成 |
| `tomato_fr3_all_full_v1` | `$PI05_RUNTIME_DIR/data/tomato_all_full_v1` | `assets/tomato_all_full_v1_30hz/` | 历史已准备且训练完成；新机器自行迁移 |

表中统计路径相对于 PI05_RUNTIME_DIR。同一内容迁移位置可设置：

```bash
export PI05_FULLTASK_DATASET_ROOT=/实际路径/tomato_fulltask_v1
export PI05_FULLTASK_ASSETS_DIR=/实际路径/assets/fulltask_c0
export PI05_ALL_FULL_DATASET_ROOT=/实际路径/tomato_all_full_v1
export PI05_ALL_FULL_ASSETS_DIR=/实际路径/assets
export PI05_SOURCE_DATA_DIR=/实际路径/harvest-tomato
```

`training_configs/datasets/` 存的是数据配置，不是数据文件：Dataset 记录 repo_id、root、sources、assets_dir、asset_id、统计摘要与 prompt 示例。实验组合通过本体适配器把它转换成训练 DataConfig。同一套数据可以被 LoRA 或全参方案引用；当前两套数据有不同来源、prompt 和统计身份，因此分别保留，版本都从 v1 开始。

原 PI05_V2_* 和 PI05_V3_* 环境变量改为上面的内容名称，请更新本机环境脚本；实际数据目录、repo_id、asset_id 和归一化摘要不重命名。

新采集、筛选或变换创建新的 dataset 版本及统计身份，不用环境变量冒充旧数据。prompt_example 仅为示例，实际英文指令读取 meta/tasks.jsonl，启动清单保存实际文本。

当前 FR3 数据使用 LeRobot v2.1，具有 meta/、data/、videos/，54 维 action、54 或 108 维原始 state 和 cam0/cam1/cam2。适配后顺序为左臂 7、左手 20、右臂 7、右手 20；双臂 delta、手部 absolute。元信息检查不能替代关节名称、单位和真实数据语义核对。

转换、验证和合并工具保留在 examples/fr3_wuji/，先读工具 --help。v3 历史来源为 0925/A、0925/B、1002_AB_190/full，441 episode、481,223 帧。不要在新机器直接运行含旧服务器路径的历史准备脚本。

计算一份新数据统计时，先建立相应实验配置：

```bash
"$UV_PROJECT_ENVIRONMENT/bin/python" -m scripts.compute_experiment_norm \
  training_configs.experiments.<负责人>.<实验模块> --stats-batch-size 512
```

目前此统计入口仅支持 FR3/Wuji，应用训练中的重排、delta 和 horizon 窗口，拒绝覆盖已有统计，可能需要下载 tokenizer。统计完成后记录文件 SHA-256 到新 Dataset.expected_norm_sha256。历史 v3 使用 expected_norm_audit_sha256，校验归一化对象的规范序列化审计摘要；它与原 JSON 文件的 SHA-256 不同，不能混用。

## 展开、检查、启动

```bash
export EXP=alice_tomato_fullft_v1_s42_run01

"$UV_PROJECT_ENVIRONMENT/bin/python" -m scripts.run_training \
  training_configs.experiments.baselines.tomato_fr3_fullft_v1 \
  --exp-name "$EXP" --dry-run

"$UV_PROJECT_ENVIRONMENT/bin/python" -m scripts.run_training \
  training_configs.experiments.baselines.tomato_fr3_fullft_v1 \
  --exp-name "$EXP" --check

CUDA_VISIBLE_DEVICES=0 "$UV_PROJECT_ENVIRONMENT/bin/python" -u -m scripts.run_training \
  training_configs.experiments.baselines.tomato_fr3_fullft_v1 \
  --exp-name "$EXP" --wandb-mode online
```

--dry-run 仅展开配置，无需数据、权重和 GPU。--check 核对元信息、fps、维度、相机角色、英文 task 和统计形状/摘要，不构建模型或下载 tokenizer；完整数据文件审计在训练启动时执行。GPU 数量仅为示例，全参模型按真实显存配置。

CLI 可临时覆盖 --batch-size 4、--num-train-steps 20000、--lr-schedule.peak-lr 1e-5；正式实验写入个人模块并提交。模型变体改动必须通过 recipe/实验文件重建 freeze_filter，不能只用 CLI 改变变体。本体改动必须提供新适配器。

新方案文件为 `recipes/pi05_lora_v1.py` 和 `recipes/pi05_fullft_v1.py`，基准实验模块分别为 `tomato_fr3_lora_v1` 和 `tomato_fr3_fullft_v1`。配置名与默认实验名也使用 v1，形成新的输出目录；历史来源单独保存在 metadata.source_baseline，不将原实验改写为 v1。

初始权重从 π0.5 base 加载，允许形状不匹配的投影层随机初始化；其他兼容权重加载，完整加载验证在训练入口执行。已有实验拒绝覆盖，使用新实验名，或对未完成的同一实验 --resume。

## 日志与 W&B

新入口自动同步终端输出到 `$PI05_RUNTIME_DIR/logs/<配置名>/<实验名>/<时间_PID>.log`，相邻 JSON 保存 commit、最终配置、来源、实际 prompt、统计文件与对象摘要、W&B 模式和结果。失败记录错误，训练入口正常返回后才标记训练完成。

checkpoint 默认位于 `$PI05_RUNTIME_DIR/checkpoints/<配置名>/<实验名>/`。原 reproducibility/ 审计继续记录完整数据文件指纹、采样计划、实际配置、统计快照和恢复契约。

W&B 必须启用。联网使用 --wandb-mode online，首次在终端登录；离线明确选择 offline，之后同步：

```bash
CUDA_VISIBLE_DEVICES=0 "$UV_PROJECT_ENVIRONMENT/bin/python" -u -m scripts.run_training \
  training_configs.experiments.<负责人>.<实验模块> --wandb-mode offline

# 恢复联网后，替换为真实 offline run 目录。
"$UV_PROJECT_ENVIRONMENT/bin/wandb" sync "$PI05_RUNTIME_DIR/wandb/offline-run-实际编号"
```

自行设置 WANDB_DIR 时以实际位置为准。日志和登录密钥不提交 Git。

## 恢复

原 commit、配置、数据、统计与实验名保持一致，加 --resume；保留完整 checkpoint、reproducibility/ 和 wandb_id.txt。已完成原预算不能通过 resume 增加步数，预算或数据变更创建新实验。

本次整理改变源码身份，不能严格恢复历史 v3 原实验。原训练 commit 为 4d9b349af63cd2cdd8ffb67d579eff04a30b34e5；新阶段可在新实验中引用其 60152/params 作为初始权重，记录父实验和新方案身份。

本轮仅确认仓库准备及测试，未重跑真实数据训练，未执行部署或实机验证。历史状态见 [迁移记录](基准迁移与归档.md)。
