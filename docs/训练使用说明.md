# 训练使用说明

本教程针对分层配置的 JAX 训练流程，包含数据、统计、日志、W&B 与恢复，不包含部署操作。

## 环境

在仓库根目录执行：

```bash
bash scripts/setup_training_env.sh
```

从空机器开始先按 [仓库 README](../README.md) 的“获取代码与安装环境”准备 Linux、NVIDIA 驱动、Git/SSH 权限、uv 和视频系统库，再克隆并执行上述安装命令。安装脚本会打印 JAX 设备及 Torch CUDA 状态；正式 GPU 训练应看到 GPU 设备与 CUDA=True，只有 CPU 时先解决驱动/设备可见性，不直接启动完整模型训练。初始权重及 tokenizer 需要联网缓存或由已准备机器迁移。

使用 Python 3.11 和 uv sync --frozen，可通过 PI05_PYTHON 选择已有解释器。环境位于仓库内 `.venv/`，下载和包缓存位于 `.cache/`，临时文件位于 `.cache/tmp/`。启动入口自动按代码所在仓库设置缓存和 W&B 路径，直接使用 .venv/bin/python 运行，不需要激活环境或手动设置运行目录。数据、归一化统计、checkpoint、日志及 W&B 使用仓库根目录的对应文件夹。保留原 JAX/Torch 和 LeRobot revision，移除 gym-aloha、MuJoCo 与 websocket 运行时依赖；RLDS 依赖仍为可选组。

默认关闭 JAX 显存预分配；每人显式选择 GPU，batch 必须能被可见设备数整除。历史 v3 使用 8 张可见 GPU、fsdp_devices=1，本轮不自动占用 GPU 启动训练。

JAX 编译缓存自动放在当前 checkout 的 `.cache/jax/`，通过入口在导入 JAX 前设置 JAX_COMPILATION_CACHE_DIR；训练循环不再覆盖到用户主目录。它保存可复用的编译结果，不是数据、权重或训练日志，不提交 Git；删除后下次运行重新编译，不影响已有 checkpoint。每个 checkout 使用自己的缓存目录。

缓存配置机制参考 [JAX 持久编译缓存说明](https://docs.jax.dev/en/latest/persistent_compilation_cache.html)。

| 实验文件中的数据设置 | 默认数据位置 | 默认统计位置 | 状态 |
| --- | --- | --- | --- |
| `baselines/tomato_fr3_lora_v1.py` | `data/tomato_fulltask_v1` | `assets/fulltask_c0/tomato_fulltask_v1_30hz/` | 占位路径；原记录未确认已准备或训练完成 |
| `baselines/tomato_fr3_fullft_v1.py` | `data/tomato_all_full_v1` | `assets/tomato_all_full_v1_30hz/` | 历史已准备且训练完成；新机器自行迁移 |

表中所有路径均相对于仓库根目录，默认按 checkout 定位，不需要再设置运行目录变量。个人实验直接修改 build_dataset()；仅在使用公共基准并需要更换实际路径时，才可用下面的可选覆盖：

```bash
export PI05_FULLTASK_DATASET_ROOT="$PWD/data/tomato_fulltask_v1"
export PI05_FULLTASK_ASSETS_DIR="$PWD/assets/fulltask_c0"
export PI05_ALL_FULL_DATASET_ROOT="$PWD/data/tomato_all_full_v1"
export PI05_ALL_FULL_ASSETS_DIR="$PWD/assets"
export PI05_SOURCE_DATA_DIR="$PWD/data/harvest-tomato"
```

数据设置直接写在个人实验文件的 build_dataset() 中。公共 Dataset 结构位于 training_configs/common.py，记录 repo_id、root、sources、assets_dir、asset_id、统计摘要与 prompt 示例，本体适配器将其转换成训练 DataConfig。同一数据可用于不同方案；版本对应数据内容，不跟随 LoRA/全参方案编号。实际数据放在仓库根目录的 data/，归一化统计放在 assets/，这些运行文件不提交 Git。

个人模板不导入其他实验，直接引用公共本体和 recipe，并包含自己的数据设置。模板使用 PI05_DATASET_ROOT 与 PI05_ASSETS_DIR 作为可选本机路径覆盖；复制到个人目录后可修改默认路径、变量名称及稳定数据身份。上面的 FULLTASK/ALL_FULL 环境变量仅是基准文件自己的约定，个人实验不必使用它们。

原 PI05_V2_* 和 PI05_V3_* 环境变量改为上面的内容名称，请更新本机环境脚本；实际数据目录、repo_id、asset_id 和归一化摘要不重命名。

新采集、筛选或变换创建新的 dataset 版本及统计身份，不用环境变量冒充旧数据。prompt_example 仅为示例，实际英文指令读取 meta/tasks.jsonl，启动清单保存实际文本。

当前 FR3/Wuji 数据使用 LeRobot v2.1，具有 meta/、data/、videos/，54 维 action、54 或 108 维原始 state 和 cam0/cam1/cam2。适配后顺序为左臂 7、左手 20、右臂 7、右手 20；双臂 delta、手部 absolute。元信息检查不能替代关节名称、单位和真实数据语义核对。

Sharpa 使用 58 维实测 state 和目标 action、左臂 7+左手 22+右臂 7+右手 22，弧度单位；cam2 左腕、cam1 右腕，两臂 delta、手部 absolute。Sharpa 数据的 state/action names 必须与协议顺序一致，具体 baseline、个人模板和命令见 [Sharpa 训练说明](Sharpa训练说明.md)。两种本体使用各自数据与统计身份。

数据转换、筛选与合并在独立的数据仓库完成，本仓库只接收准备好的数据，保留校验与归一化统计计算。v3 历史来源为 0925/A、0925/B、1002_AB_190/full，441 episode、481,223 帧；历史归档仅用于溯源，不作为当前数据准备入口。

### 数据校验流程

1. 将数据仓库产出的 LeRobot 数据集放入 data/，在个人实验 build_dataset() 写入路径、repo_id、来源与英文 prompt 示例；确认所选本体的关节顺序和单位与数据一致。
2. 先对实验执行 --dry-run 检查最终路径和参数，此步不读取数据。新数据还没有统计时，执行下方 scripts.compute_experiment_norm 命令；它先做数据元信息检查，再按训练变换读取向量和动作窗口、计算统计并记录绑定。已有统计时，同时准备 norm_stats.json 与 norm_metadata.json。
3. 执行 scripts.run_training 的 --check。检查 LeRobot v2.1 元信息、必要目录、非空帧数/episode 数、fps、state/action 维度、相机字段及英文 task，再检查统计形状/数值、文件摘要和实际数据/输入变换绑定。失败会退出并说明原因，根据错误修正配置或在数据仓库处理数据；检查通过后使用同一模块启动训练。
4. 正式启动再次执行上述检查，并通过 LeRobot 加载实际数据表，核对元信息帧数与实际加载帧数；为 meta/data/videos 文件计算摘要，记录帧身份和采样审计。训练采样时读取对应图像与动作。摘要检查用于固定数据版本，不代表已全量解码视频，也不能证明视频与动作在语义上对齐。

--dry-run、--check 和正式启动的完整命令见下方“展开、检查、启动”。--check 需要统计，不能当作不带统计的完整数据验收工具。关节左右顺序、单位、任务含义仍需数据生产者确认。

需要将数据与原始 FR3/Wuji 采集记录额外对照时，可以运行独立校验工具：

```bash
.venv/bin/python -m examples.fr3_wuji.verify_dataset \
  --src-root data/raw_captures \
  --root data/tomato_fulltask_v1 \
  --repo-id fr3_wuji/tomato_fulltask_v1 \
  --episodes 2 --samples 6
```

两个路径都必填：src-root 是原始逐 episode 采集目录的父目录，root 是准备好的目标 LeRobot 数据集；前者需带采集时的 dataloader.py。工具按源采集目录的数字顺序与目标 episode 顺序对照，因此不能直接用于已筛选、重排或合并后顺序不同的数据。它抽样检查 episode 长度、episode 索引及 state/action 数值一致性，另外选取运动图像与前后邻帧比较对齐。默认仅检查前两个 episode，不是全量验收；缺少原始数据时跳过此项，仍可执行实验 --check。

输出 FAIL 会报错退出；OK 表示本次抽样通过。图像比较只排除相同或几乎静止的源帧，discriminability 默认是源图像间平均像素差阈值 2（uint8 范围 0–255），不随目标图像误差增大；重新编码造成的疑似对齐失败仍需人工复核。静止画面等情况无法形成有效邻帧比较时显示 VECTOR_OK_ALIGNMENT_UNVERIFIED，表示向量抽样通过、图像对齐未验证，不能将零次对齐比较当成通过。这个工具不生成或转换训练数据。

计算一份新数据统计时，先建立相应实验配置：

```bash
.venv/bin/python -m scripts.compute_experiment_norm \
  training_configs.experiments.<负责人>.<实验模块> --stats-batch-size 512
```

目前此统计入口支持 FR3/Wuji 和 FR3/Sharpa，应用各自训练中的输入适配、delta 和 horizon 窗口，可能需要下载 tokenizer。它将 norm_stats.json 与 schema_version=2 的 norm_metadata.json 成对发布：记录统计文件摘要、数据身份/帧数/episode 数、元信息与 Parquet 文件摘要、动作维度/频率/horizon、输入变换配置及实现摘要。计算前后会核对输入文件，发现途中变更就拒绝保存；启动前重新核对对应关系，避免把另一份数据的统计拿来训练。

同一统计目标采用非阻塞目录锁，第二个计算进程会报错；不同 asset_id 可分别计算。两个文件先写入 assets 父目录下同一文件系统的隐藏临时目录，全部成功后原子重命名为最终 asset_id 目录，训练只能读到完整发布的统计。已有目标目录拒绝覆盖，包括空目录或历史残留目录；准备新统计时只准备父目录，使用新的 asset_id。普通异常会清理临时目录并释放锁，可再次计算；强制杀进程后可能留下隐藏 .building-* 临时目录，确认没有相关计算进程后可手动清理，训练不会读取它。文件锁依赖文件系统支持，共享盘跨主机仍需统一任务调度，不作为跨主机分布式锁承诺。

这些检查会读取 meta/ 和 data/ 下的文件计算摘要，不解码视频、不下载 tokenizer；--check 因此可能需要一定磁盘读取时间。数据与统计搬迁时保留文件内容及数据内部相对路径，并同时复制两个统计文件。同一数据可跨 LoRA/全参方案和学习率/batch 复用；改数据、输入变换实现或 horizon 后建立新统计身份并重算。可额外将统计文件 SHA-256 填入 Dataset.expected_norm_sha256，固定发布文件。

关节全程不变属于允许的常量维度：保留真实 std=0 和相等分位数，通过现有 epsilon 进行归一化，不伪造变化。工具提示零方差维度，并写入 norm_metadata.json 的 constant_dimensions；非有限数值、负标准差或颠倒的分位数仍拒绝。

旧统计没有上述绑定时默认拒绝，优先在新的 asset_id 下重新计算。只有人工确认来源的历史统计，才在该实验的 Dataset 明确设置 allow_legacy_norm_stats=True，并同时固定 expected_norm_sha256 或 expected_norm_audit_sha256；已有元数据中的身份、帧数、episode 数和 horizon 仍不能与本次数据矛盾。启动清单会标为 legacy_pinned 并输出兼容提示，表示仅验证固定统计摘要，没有新格式的数据/变换绑定。全参基准已对已知历史统计显式启用此设置，新数据不要沿用。

历史 v3 使用 expected_norm_audit_sha256，校验归一化对象的规范序列化审计摘要；它与原 JSON 文件的 SHA-256 不同，不能混用。两种摘要都会先校验，再处理绑定或旧格式兼容。

## 展开、检查、启动

```bash
export EXP=alice_tomato_fullft_v1_s42_run01

.venv/bin/python -m scripts.run_training \
  training_configs.experiments.baselines.tomato_fr3_fullft_v1 \
  --exp-name "$EXP" --dry-run

.venv/bin/python -m scripts.run_training \
  training_configs.experiments.baselines.tomato_fr3_fullft_v1 \
  --exp-name "$EXP" --check

CUDA_VISIBLE_DEVICES=0 .venv/bin/python -u -m scripts.run_training \
  training_configs.experiments.baselines.tomato_fr3_fullft_v1 \
  --exp-name "$EXP" --wandb-mode online
```

--dry-run 仅展开配置，无需数据、权重和 GPU。--check 核对元信息、fps、维度、相机角色、英文 task、统计形状/摘要以及数据和变换绑定，不构建模型或下载 tokenizer；包含视频的完整数据文件审计在训练启动时执行。GPU 数量仅为示例，全参模型按真实显存配置。

CLI 可临时覆盖 --batch-size 4、--num-train-steps 20000、--lr-schedule.peak-lr 1e-5；正式实验写入个人模块并提交。模型变体改动必须通过 recipe/实验文件重建 freeze_filter，不能只用 CLI 改变变体。本体改动必须提供新适配器。

log_interval、save_interval 和 action_horizon 必须为正整数，keep_period 必须为 None 或正整数；配置构造时验证，dry-run 和直接训练入口也会拒绝非法设置。统计与 --check 完成后提交个人配置、记录 commit，正式训练固定该 checkout，避免启动后改变源码审计。

新方案文件为 `recipes/pi05_lora_v1.py` 和 `recipes/pi05_fullft_v1.py`，基准实验模块分别为 `tomato_fr3_lora_v1` 和 `tomato_fr3_fullft_v1`。配置名与默认实验名也使用 v1，形成新的输出目录；历史来源单独保存在 metadata.source_baseline，不将原实验改写为 v1。

初始权重从 π0.5 base 加载，允许形状不匹配的投影层随机初始化；其他兼容权重加载，完整加载验证在训练入口执行。已有实验拒绝覆盖，使用新实验名，或对未完成的同一实验 --resume。

## 日志与 W&B

以下日志与 checkpoint 路径均相对于仓库根目录。启动器自动同步终端输出到 `logs/<配置名>/<实验名>/<时间含微秒_PID>.log`，相邻 JSON 保存 commit、最终配置、来源、实际 prompt、统计文件与对象摘要、W&B 模式、本次日志段和结果。失败记录错误，训练入口正常返回后才标记训练完成。

checkpoint 默认位于 `checkpoints/<配置名>/<实验名>/`。每个 step 子目录包含 params/（权重）、train_state/（恢复状态）及 assets/（对应统计）。原 reproducibility/ 审计继续记录完整数据文件指纹、采样计划、实际配置、统计快照和恢复契约。

W&B 必须启用。联网使用 --wandb-mode online，首次在终端登录；离线明确选择 offline，之后同步：

```bash
CUDA_VISIBLE_DEVICES=0 .venv/bin/python -u -m scripts.run_training \
  training_configs.experiments.<负责人>.<实验模块> --wandb-mode offline

# 恢复联网后，替换为真实 offline run 目录。
.venv/bin/wandb sync wandb/offline-run-实际编号
```

启动器将 WANDB_DIR 设置为仓库根目录，运行记录保存在 wandb/。每次启动和 checkpoint 续训都创建独立 run ID，同一实验以 wandb_id.txt 中的首个 ID 作为固定 group，联网/离线及模式切换采用同一规则。训练从 checkpoint 恢复，不调用 W&B 的 resume；这避免离线 SDK 忽略 resume，以及 checkpoint 落后于已有日志时历史步数冲突。云端看到同组的多个日志段，不能将其当成自动拼接的一条曲线；使用各段记录的 start_step 判断覆盖范围，未保存步数重算时可能重叠。[W&B run/group 与 step 说明](https://docs.wandb.ai/ref/python/experiments/run/)

每段记录保存在 checkpoint 根目录的 wandb_sessions/<run_id>.json，包含 mode、root_run_id、start_step、项目/账号、本地 run_directory 和运行结果；wandb_latest_session.json 指向最近一段，启动器运行清单也记录本次段信息。正常退出和可捕获失败会 finish W&B、保存结果并关闭 checkpoint manager；强制杀进程可能保留 running 状态，需结合 checkpoint 与本地日志判断。

离线恢复仍使用 --resume --wandb-mode offline。恢复联网后先 wandb login，再按每个离线记录里的 run_directory 逐段执行 wandb sync；每段独立 ID，不需要 --append，也不会自动上传其他段。切换 online 续训可直接创建新段，旧离线段仍须自行同步。向另一台电脑迁移日志后，run_directory 的旧绝对路径需替换为迁移后的实际目录。团队账号可以通过 W&B 登录及 WANDB_ENTITY 选择。日志、登录密钥与本地 W&B 文件不提交 Git。

## 恢复

原 commit、配置、数据、统计与实验名保持一致，加 --resume；迁移时保留完整实验目录，包括 step 下的 train_state/、params/、assets/，根 reproducibility/、wandb_id.txt 及 wandb_sessions/，同时保留未同步的 wandb/ 日志段。训练从最新有效 checkpoint 的完成步数继续；只有导出的 params 不能精确续训。checkpoint 目录不存在或无有效保存时明确报错，不退回从头训练；编号为 0 的实际 checkpoint 也可恢复。已完成原预算直接退出，不生成新 W&B 日志段；预算或数据变更创建新实验。

迁移数据/统计的存放路径可以变化，但内容与内部相对路径必须一致。源码、实验配置和训练恢复契约保持原版本，不能在新 main 上直接恢复旧运行。

本次整理改变源码身份，不能严格恢复历史 v3 原实验。原训练 commit 为 4d9b349af63cd2cdd8ffb67d579eff04a30b34e5；新阶段可在新实验中引用其 60152/params 作为初始权重，记录父实验和新方案身份。

本轮仅确认仓库准备及测试，未重跑真实数据训练，未执行部署或实机验证。历史状态见 [迁移记录](基准迁移与归档.md)。
