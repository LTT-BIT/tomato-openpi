## 2026-10-14：排查 Blackwell 多卡训练非法显存访问

- 修复 JAX 多卡训练记录 W&B 样例图时逐项索引全局分片数组的问题；现在只把一个本地设备分片复制到主机生成预览，避免为了预览跨卡聚合 batch。
- 生产数据诊断结果：单卡全参一步训练通过；两卡和八卡 FSDP 均在真实训练步触发 CUDA 700 / NCCL `ncclGroupEnd`，与 batch 64、DataLoader worker 和 NCCL P2P 无关；纯八卡 NCCL all-reduce 与 all-gather 通过。
- 当前环境使用 NCCL 2.26.2，与 NVIDIA NCCL 已确认的 RTX PRO Blackwell 大集合通信非法访问问题一致；`NCCL_PROTO=LL` 在本训练图中仍失败。隔离加载 NCCL 2.31.2 后，两卡真实训练步不再出现 CUDA 700，说明运行时 NCCL 升级可以解决该故障。
- 升级 NCCL 后的首次两卡测试在指标记录阶段停止，原因是服务器仓库停留在 `fb03ef2`，而测试脚本来自较新的本地版本，旧 `DataLoaderImpl` 没有 `sampling_progress` 接口；该错误属于代码版本错配，与 GPU/NCCL 无关。
- 将服务器仓库快进到本地版本后，NCCL 2.31.2 下两卡 global batch 2、八卡 global batch 8、八卡正式 baseline global batch 64 的真实一步训练均通过；每次都完成前向、反向、参数更新、采样指标、W&B offline 记录和 checkpoint 写入，测试 checkpoint 已清理。
- 发布版本化公共环境 `/mnt/data/public_tools/training/environments/pi05/20261014`：复用 `20261011` 的 Python 与系统库，通过公共 `run-python` 预加载校验过的 NCCL 2.31.2，旧环境保持不变；仓库默认入口和服务器文档已切换到新版本。
